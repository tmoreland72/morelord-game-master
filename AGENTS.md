# Morelord Game Master

Follow `../morelord-core/AGENTS.md`, `../morelord-core/MORELORD-BRAND-GUIDE.md`,
and `../morelord-core/IN-GAME-TESTING.md` before changing this module.

- Morelord Core is required. Reuse its UI, participation, user filtering, skill
  rolls, and contextual socket service; do not recreate these locally.
- Configure participants on the Player Settings tab. Party requests, selected-token requests, and single-character checks use this shared scope.
- Requests stay in chat, never player popup dialogs. Eligible online players may
  roll their characters. Any GM may roll for anyone, including inactive players.
- The check builder and each private specialty request have a saved Blind roll toggle. Roll of Fate stays public and has no blind toggle. Blind results and summaries are GM/Assistant-only; non-blind results are public. Never return private totals in request flags or acknowledgements.
- Show check results only as chat cards, never in the Game Master tray.
- Preserve the bottom tray. Tabs are Roll Requests, Bulk Actions, Macros, Sound, Triggers, Cheat Sheet, GM Settings, and Player Settings. Roll Requests keeps the check builder on one row, then shows enabled specialty requests as compact cards in a grid. There are no section or column headers.
- The check builder stays on one line inside a card with the same border, background, and padding as the specialty cards: type, skill or ability, optional DC, who rolls, Blind roll when it can be private, and the dice button. Each field label sits above its control. Specialty cards place the request name above one row: the selector fills the remaining space, then Blind roll, then the dice button. Roll of Fate has no blind toggle, so its row is Who rolls and the dice button. Delerium Search keeps the Craftworks search-area selector and the showDeleriumSearch world toggle.
- Roll Requests, Macros, Triggers, and Cheat Sheet have no outer surface frame.
- Cheat Sheet is a GM-only reference of paraphrased SRD 5.2.1 rules. Dense chips sit in a wrapping grid under small section headers. Hover and keyboard focus open a Foundry tooltip: a bold title, bold subheadings for parts of a rule, and short bullets or a small table. The tab does not show a license line. Sections are Conditions, Actions in combat, Improvising damage, Misc, then Cover and vision, unless GM Settings hides or reorders them. Misc is one chip each for Typical DC, Exhaustion, Jumping, Travel Pace, Mounted, and Underwater. Drakkenheim is one section when `drakkenheim-core`, `drakkenheim-monsters`, or `drakkenheim-scgd` is active and the section is shown. Its chips are static original summaries: one Contamination chip (levels 1–6), Delerium Search, and Delerium sizes in ascending value. Two or more failed search checks draw a random encounter. The content conditions join Conditions as purple chips: Addled, Bewildered, Bleeding, Bloodied, Burning, Clumsy, Dazed, Defenseless, Distracted, Enfeebled, Entangled, Frozen, Helpless, Immobilized, Jinxed, Shocked, Sickened, Slowed, Staggered, Valor, and Weakened. Mutations, madness, and container titles are omitted. The sheet does not read compendium text. `api.debugDrakkenheimCheat()` reports the active modules and the static chips. Craftworks is not consulted.
- Per-world GM toggles live on the GM Settings tray tab. Roll Requests, Bulk Actions, Triggers, and Cheat Sheet are separate sections. Each row has a grip icon, a show/hide toggle, and drag reordering. Those choices are world settings only a GM can change, and they default on so an upgrade hides nothing. Hidden rows keep their place. The matching tab uses that order and skips hidden items. Ambience and other module configuration stay in Foundry Game Settings. Ambience is a list of source folders a GM can add or remove with the folder FilePicker. The list starts empty. A previous single folder is copied once only when that saved value has a path. That value is read from the setting document by its key. A world whose list was emptied while that path was still stored gets the folder back once, and the old setting is then cleared so a folder the GM removes stays removed. The Game Master settings dialog stays non-modal so the browser can be used. Add folder opens the browser at the data root, including when ambience rows already exist and when the file browser remembers another directory, and the chosen folder is added to the list before Save. Each folder is scanned recursively, and its FilePicker source is kept. A missing or invalid folder is skipped, with a console warning and one notice. Saved ambience buttons store full file paths.
- Playlists and Ambience share one full-width row. The name button stretches to fill the column, and the trash icon is a fixed square at the right end of that same row. Add Playlist and Add Ambience are accent buttons as wide as those rows, aligned with the trash button. Volume and stop actions stay full width. Every module button uses one shared height, except Macros pins, which use a taller height so the icon fits with padding. Saved sound buttons use Core trash-icon deletion controls. Field labels sit above their fields. Controls keep that shared height and do not stretch. Player Settings uses the same section heading as the other tabs.
- Starting music stops other music first and uses native shuffle; ambience remains separate. Add Playlist starts the chosen playlist at the dialog volume and opens with no playlist selected. Add clears that choice. Add Ambience lists each layer on one compact grid row: checkbox, file name, help icon, and volume. One Name field above the list names the whole mix. That field starts empty, and Add requires the GM to type the group name. Saved buttons show that name. Now Playing titles each layer with its file name and uses the group name as the subtitle. The help icon tooltip (`data-tooltip`, direction LEFT) shows the full path. The button says Add. Layers start unchecked at the world's remembered ambience volume. An empty Name warns, leaves Add Ambience open with the selected layers and volumes intact, and focuses the Name field. Choosing no playlist, no sound, no character, or a volume outside 0–100 warns the same way and leaves that dialog open on the field that needs attention. Ambience uses the same full-width row as Playlists. The tray stays above the canvas and Foundry windows, and a rebuild keeps in-progress fields. Opening Foundry Game Settings closes the tray, including this module's Configure menu. Calling for a roll, applying any bulk action, or running a macro also closes the tray. A bulk action that changes nothing still closes it. Sound controls, including Stop All Sound, leave it open. The handle opens it again. Sound levels use Foundry's volume curve. PlaylistSound volume is stored at hundredths by Foundry's server-side field clean, so Set All Track Volumes writes the hundredth closest to the chosen percent on playlist songs only. Set Ambience Volumes sets currently playing ambience and remembers that percent for the next Add Ambience. Stop All Sound stops every playlist, every ambience layer, and every sound Foundry still has playing. Bulk Actions puts Coins and XP on the first row. Inspiration, Prototype Token Sync, and Undo Last Action share the second row at equal height. Apply sits beside its field. Inspiration undo records a grant or clear that changes a character.
- Skill, ability, save, foraging, and death-save chat cards show a single Roll button. That button uses the dnd5e native roll, including the system's roll dialog and automatic modifiers.
- Delerium Search reuses Craftworks rules and rewards with Game Master's chat UI.
- Blind death saves keep sheet counters unchanged; public death saves retain native updates.

- Derive saved sound labels from playlist names and the ambience names the GM saved.
- Call for Roll actions are not saved buttons; save all control changes immediately for next time. Encounter dice use a dropdown.
- Create skill summaries only after every roll card exists; retain averages for single-player checks.
- Delerium summaries have no average; reuse Craftworks rewards/encounters and expose their actions.
- Macros follows Bulk Actions, starts empty, and accepts dragged macros without a ten-slot limit.
- Triggers use native spell provenance and qualifying Sneak Attack hits, with once-per-turn damage. Managed macros call the module API. Sneak Attack adjacency is measured on the target token's scene.

- Foraging reuses Journeys terrain/DC configuration and food rules, with chat requests and complete-only summaries respecting visibility.
- Macro pins are compact rows: the icon is on the left and the name is on the right. Long names truncate with an ellipsis, and the full name is available on hover. Left click executes. Dragging a pin reorders it and saves that order immediately for the world; the drag does not execute the macro. Dropping a new macro still pins it. The right-click menu removes the pin, and it can mark the pin to run when the world loads. Run on load for me is stored for that user and runs only on that user's client. Run on load for everyone is stored for the world, only a GM can change it, and it runs on every client, including players. A pin marked both ways runs once. A for-me pin shows the blue user icon. A pin marked for everyone shows only the gold group icon.
- The Triggers tab does not create triggers. Trigger behavior stays in module code. The tray can enable, pause, and show each trigger.
- Sorcerer triggers request a blind d20 first; threshold starts at 1, increases per missed d20, and resets after a surge table roll.

- Wild Magic and Sneak Attack triggers match class/subclass/feature identifiers, not named characters. Surge thresholds and once-per-turn Sneak Attack limits are separate per character. Preserve existing rule IDs and counters.

- Trigger timing: Wild Magic waits for the spell attack roll, or casting completion when no attack is required; Sneak Attack waits for the linked weapon damage card. Do not trigger on the initial usage/attack card.
- Give every popup form a distinct stable ID so Core retains its size independently.

Roll Requests uses one check builder and a card grid for each enabled specialty: Encounter Check, Delerium Search, Foraging Check, Death Save, and Roll of Fate. The grid is three columns when the tray is wide, two when it is medium, and one when it is very narrow. Hidden specialties leave the grid without an empty cell. Encounter uses the die dropdown. Delerium Search uses the Craftworks search area. Roll of Fate chooses among the Player Settings party or the selected character tokens. Blind roll defaults off for unconfigured private cards; saved choices remain sticky.

Trigger cards are only as tall as their content. The header is one row: name, scope, status icon, and play/pause. When and Then sit tightly under that row. The status icon shows Running or Stopped; the card does not repeat that word. Icons have tooltips and accessible labels. Edit and Delete stay hidden.

All roll-request cards are public, including Wild Magic d20 requests; assigned-player/GM roll permissions still apply. Blind results and summaries remain private. Pending legacy request cards are made public when their active GM loads the module. Wild Magic never waits for optional damage; Sneak Attack still waits for weapon damage.

- Before any in-Foundry testing, verify the loaded world ID is `dev1` (Dev1). If another world is loaded, or its identity cannot be verified, skip all in-Foundry testing without switching worlds. An explicit user instruction to skip testing takes precedence even in Dev1.

- Trigger definitions are global across worlds on the same Foundry installation. Macros, saved roll requests, sound buttons, and remembered options are world-specific.
- World Clock defaults to 10 game minutes per real minute; game pause and started combat suspend its timer. Defer combat time and add 6 seconds per round on combat end without double-counting native advancement. Preserve manual calendar adjustments. Hex-map timing is future work.

- Keep per-version release notes in `release-notes/`. Put temporary scripts, staging folders, browser profiles, and other working files in the owning module's `/tmp/` directory; ignore `/tmp/` in Git and exclude it from release archives. Preserve permanent source, documentation, and regression evidence.

- Token Distance Indicator is registered by Morelord Core. Core's history has no Force choice; it was a per-client checkbox. Game Master promotes that registration to a world setting only a GM can change, which is the forced table-wide value. Every client reads it. A GM's previous client off value is copied once when the world has not saved the setting.
- Every `game.settings.register` in this module is world-scoped and `restricted`, so a player cannot override it, except Run on load for me. That list is client-scoped because it belongs to one user, and it stays `restricted` so only a GM can change their own list. Run on load for everyone stays a world setting. The Alt+G binding stays a per-user Foundry keybinding because it is a local shortcut, and it remains GM-only. Core window geometry stays per user and is not registered here.
- Bulk Actions uses the Player Settings scope for coins, XP, inspiration, and prototype token sync. The menu order is Coins, XP, then Inspiration and Prototype Token Sync side by side in one compact card row, then Undo Last Action. That shared row uses the specialty-card grid and becomes two columns once the tray is wide enough for two cards. Coin and XP splits give the entire remainder to one random party member: leftover copper for coins, leftover XP for experience. Giving an amount to each member adds the full amount to everyone. Setting party XP replaces each member's experience with the entered non-negative amount. Coin removal spends personal currency first, then the shared D&D5e Party/Group purse, and reports any unpaid deficit without negative balances. Inspiration grants Heroic Inspiration only to characters who do not already have it, and clears it only for characters who do. XP, coins, and prototype token sync also skip a character who would not change. Only characters who change are stored for undo. If nobody changes, the previous undo stays and a notice says so. Prototype Token Sync copies the current scene token onto the prototype token for linked and unlinked actors and skips characters with no placed token. The copied settings are name, name display, actor link, image and scale, width, height, depth, disposition, resource bar display, primary resource bar, secondary resource bar, vision, detection modes, light, lock rotation, rotation, opacity, dynamic ring, and occlusion. The tray card stays short. Its help icon shows that description in Foundry's tooltip and opens that list. The XP action explanation is the same kind of help icon beside the Action label. Changing the Roll Requests type replaces the second dropdown with the SRD 5.2 skills, or with the six abilities for an ability check or saving throw, and keeps the selected value inside that list. Only settings that differ are written, so a prototype Foundry would leave unchanged does not cancel the update. Editing a tray field does not rebuild the tray before the following click. Undo Last Action restores only the latest bulk action from its world setting and enables as soon as that action finishes. Every applied operation posts a standard public Core chat card. The Coins addition button and the XP button read Apply from the localization strings. Coin removals still read Take.

## Releases and documentation

- Every release maintains the cumulative root `CHANGELOG.md` (newest version first, `#`/`##`/`###` headings with spaces after `#`, `- ` bullets, no `---` horizontal rules) alongside `release-notes/RELEASE-NOTES-<version>.md`.
- `release-notes/` is export-ignored, so the installed module gets the changelog from `./CHANGELOG.md`. Keep that file at the repository root. A legacy `release-notes/<version>.md` note is included when `RELEASE-NOTES-<version>.md` is absent.
- Regenerate `CHANGELOG.md` with `node scripts/changelog.cjs` after editing release notes. `node scripts/changelog.cjs --check` verifies it. The manifest release sync refuses to publish when those notes exist and `CHANGELOG.md` is stale. Omit `## Verification` and other internal test sections from the cumulative file.
